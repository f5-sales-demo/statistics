Use the discovered `XCSH_VIRTUAL_HOST` to read traffic arriving at the load balancer and forwarding toward its origin.

| Metric | Meaning | Returned unit |
| --- | --- | --- |
| `HTTP_REQUEST_RATE` | HTTP requests per second | `UNIT_REQUESTS_PER_SECOND` |
| `HTTP_ERROR_RATE`, `HTTP_ERROR_RATE_4XX`, `HTTP_ERROR_RATE_5XX` | Error rates by response class | `UNIT_ERRORS_PER_SECOND` |
| `REQUEST_THROUGHPUT`, `RESPONSE_THROUGHPUT` | Request and response bit rate | `UNIT_BITS_PER_SECOND` |
| `HTTP_INGRESS_REQUEST_RATE`, `HTTP_EGRESS_REQUEST_RATE` | Incoming and outgoing request rate | `UNIT_REQUESTS_PER_SECOND` |
| `REQUEST_TO_ORIGIN_RATE` | Requests forwarded to origin per second | `UNIT_REQUESTS_PER_SECOND` |
| `CLIENT_RTT`, `SERVER_RTT` | Average client/server round-trip time | `UNIT_SECONDS` |
| `HTTP_RESPONSE_LATENCY` and its percentile selectors | Response latency | Read each returned `unit` |

These measurements have different scopes and sampling behavior; ingress, egress, and origin rates need not match exactly. They do not produce exact request counts. Use [HTTP access logs](../access-logs/) for counts, and [origin performance](../origin-performance/) to isolate the matched destination.

Ingress and egress selectors require `group_by: ["VHOST"]` for this deployment. Combining them with `SERVICE` grouping can return HTTP 500.

1. Build a request grouped by virtual host.

   ```bash
   XCSH_REQUEST="$(jq -nc --arg ns "$XCSH_NAMESPACE" --arg start "$XCSH_START_TIME" \
     --arg end "$XCSH_END_TIME" --arg vh "$XCSH_VIRTUAL_HOST" '{
       namespace: $ns, start_time: $start, end_time: $end,
       step: "5m", range: "5m", group_by: ["VHOST"],
       label_filter: [{label: "LABEL_VHOST", op: "EQ", value: $vh}],
       field_selector: {node: {metric: {upstream: [
         "HTTP_REQUEST_RATE", "HTTP_ERROR_RATE", "HTTP_ERROR_RATE_4XX",
         "HTTP_ERROR_RATE_5XX", "HTTP_RESPONSE_LATENCY",
         "REQUEST_THROUGHPUT", "RESPONSE_THROUGHPUT", "REQUEST_TO_ORIGIN_RATE",
         "CLIENT_RTT", "SERVER_RTT", "HTTP_SERVER_DATA_TRANSFER_TIME",
         "HTTP_INGRESS_REQUEST_RATE", "HTTP_EGRESS_REQUEST_RATE",
         "HTTP_RESPONSE_LATENCY_PERCENTILE_50",
         "HTTP_RESPONSE_LATENCY_PERCENTILE_90",
         "HTTP_RESPONSE_LATENCY_PERCENTILE_99",
         "ACTIVE_CONNECTIONS", "NEW_CONNECTION_RATE"
       ]}}}
     }')"
   ```

2. Query and summarize the returned series.

   ```bash
   XCSH_TRAFFIC_JSON="$(curl --silent --show-error --fail-with-body --max-time 60 \
     --request POST \
     --header "Authorization: APIToken ${XCSH_API_TOKEN}" \
     --header 'Content-Type: application/json' \
     --data-binary "$XCSH_REQUEST" \
     "${XCSH_API_URL}/api/data/namespaces/${XCSH_NAMESPACE}/graph/service")"
   jq -er --arg vh "$XCSH_VIRTUAL_HOST" '
     def summary: {type, unit, points: (.value.raw | length),
                   latest: (.value.raw[-1] // null)};
     {step, virtual_host: $vh,
      metrics: ([.data.nodes[]? | select(.id.vhost == $vh)
        | .data.metric.upstream[]? | summary] | sort_by(.type)),
      unavailable: (["ACTIVE_CONNECTIONS", "NEW_CONNECTION_RATE"] -
        [.data.nodes[]? | select(.id.vhost == $vh) | .data.metric.upstream[]?.type])}
   ' <<<"$XCSH_TRAFFIC_JSON"
   ```

`points` counts metric samples, not requests. `latest.timestamp` is the returned bucket time in Unix seconds, which can precede capture time. Empty connection series remain supported but unavailable in this demo window. Inspect `latest.value` together with `unit`; preserve a surprising returned unit instead of silently relabeling it.

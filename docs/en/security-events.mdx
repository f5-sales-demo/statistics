Security events confirm web application firewall (WAF) actions for the selected virtual host. The API returns events as JSON-encoded strings; decode each string to read the event fields.

## Query scope

Query `XCSH_NAMESPACE` and the discovered `XCSH_VIRTUAL_HOST` over the 24-hour `XCSH_START_24H`–`XCSH_END_TIME` window. Select `action="block"` and at most three events; the current demo requires its WAF and rejection traffic.

## Request procedure

1. Build a virtual-host and block-action query.

   <div data-xcsh-context="shell" data-xcsh-fields="XCSH_VIRTUAL_HOST XCSH_NAMESPACE" data-xcsh-render="inline">

   ```bash
   XCSH_EVENT_QUERY="$(jq -nr --arg vh "<XCSH_VIRTUAL_HOST>" \
     '"{vh_name=\"" + $vh + "\",action=\"block\"}"')"
   XCSH_REQUEST="$(jq -nc --arg ns "<XCSH_NAMESPACE>" --arg start "$XCSH_START_24H" \
     --arg end "$XCSH_END_TIME" --arg query "$XCSH_EVENT_QUERY" '{
       namespace: $ns, start_time: $start, end_time: $end,
       limit: 3, sort: "DESCENDING", query: $query
     }')"
   ```

   </div>

2. Query the events.

   <div data-xcsh-context="shell" data-xcsh-fields="XCSH_API_TOKEN XCSH_API_URL XCSH_NAMESPACE XCSH_VIRTUAL_HOST" data-xcsh-render="inline">

   ```bash
   curl --silent --show-error --fail-with-body --request POST \
     --header "Authorization: APIToken <XCSH_API_TOKEN>" \
     --header 'Content-Type: application/json' \
     --data-binary "$XCSH_REQUEST" \
     "<XCSH_API_URL>/api/data/namespaces/<XCSH_NAMESPACE>/app_security/events" |
   jq -er --arg ns "<XCSH_NAMESPACE>" --arg vh "<XCSH_VIRTUAL_HOST>" '{
     total_hits: (.total_hits | tonumber),
     returned: (.events | length),
     events: [.events[]? | (if type == "string" then fromjson else . end)
       | select(.namespace == $ns and .vh_name == $vh)
       | {time, namespace, vh_name, action, sec_event_type,
          sec_event_name, rsp_code, app_firewall_name}]
   }'
   ```

   </div>

## Empty security-event metric response

Security-event metrics aggregate counters separately from the event-log API above. Select `XCSH_NAMESPACE` and `XCSH_VIRTUAL_HOST` over the fixed two-hour window, grouped by `VH_NAME` and `SEC_EVENT_TYPE`.

1. Build a namespace and virtual-host metrics selector for the fixed two-hour window.

   <div data-xcsh-context="shell" data-xcsh-fields="XCSH_NAMESPACE XCSH_VIRTUAL_HOST" data-xcsh-render="inline">

   ```bash
   XCSH_REQUEST="$(jq -nc --arg ns "<XCSH_NAMESPACE>" --arg start "$XCSH_START_TIME" \
     --arg end "$XCSH_END_TIME" --arg vh "<XCSH_VIRTUAL_HOST>" '{
       namespace: $ns, start_time: $start, end_time: $end,
       step: "5m", group_by: ["VH_NAME", "SEC_EVENT_TYPE"],
       label_filter: [{label: "VH_NAME", op: "EQ", value: $vh}]
     }')"
   ```

   </div>

2. Query security-event metrics.

   <div data-xcsh-context="shell" data-xcsh-fields="XCSH_API_TOKEN XCSH_API_URL XCSH_NAMESPACE" data-xcsh-render="inline">

   ```bash
   curl --silent --show-error --fail-with-body --max-time 60 --request POST \
     --header "Authorization: APIToken <XCSH_API_TOKEN>" \
     --header 'Content-Type: application/json' \
     --data-binary "$XCSH_REQUEST" \
     "<XCSH_API_URL>/api/data/namespaces/<XCSH_NAMESPACE>/app_security/metrics" |
   jq -er '{data, step}'
   ```

   </div>

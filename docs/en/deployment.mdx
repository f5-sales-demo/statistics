The Terraform root pins `f5-sales-demo/xcsh` 15.0.0 and immutable commits of the [origin
server](https://github.com/f5-sales-demo/origin-server) and [traffic
generator](https://github.com/f5-sales-demo/traffic-generator). It uses the signed-in Azure
subscription, uses the selected deployer and environment, and stores local state under
`$HOME/.local/state/statistics`. The two default East US 2 VMs are `Standard_D16s_v3` and
`Standard_F16s_v2`.

## Prepare Terraform

Use Terraform 1.8 or later and the Azure CLI in your prepared Bash session. For a running deployment, use its existing local state; initializing a different state path can recreate resources.

1. Sign in to Azure and select the approved demo subscription:

   <div data-xcsh-context="shell" data-xcsh-fields="XCSH_AZURE_SUBSCRIPTION_ID">

   ```bash
   az login
   az account set --subscription '<XCSH_AZURE_SUBSCRIPTION_ID>'
   ```

   </div>

2. Bind Terraform to that subscription:

   <div data-xcsh-context="shell" data-xcsh-fields="XCSH_AZURE_SUBSCRIPTION_ID">

   ```bash
   export TF_VAR_subscription_id="$XCSH_AZURE_SUBSCRIPTION_ID"
   export TF_CLI_CONFIG_FILE=/dev/null
   ```

   </div>

## Review the plan

For a first deployment, confirm that the hostname and named namespace objects are unowned. For this running demo, use the owner’s existing private state.

1. Create the private state directory.

   ```bash
   XCSH_STATE_DIR="${XDG_STATE_HOME:-$HOME/.local/state}/statistics"
   install -d -m 0700 "$XCSH_STATE_DIR"
   ```

2. Initialize the local backend.

   ```bash
   terraform -chdir=terraform init -input=false \
     -backend-config="path=$XCSH_STATE_DIR/terraform.tfstate"
   ```

3. Validate the configuration.

   ```bash
   terraform -chdir=terraform validate
   ```

4. Save a plan outside Git.

   ```bash
   terraform -chdir=terraform plan -input=false \
     -out="$XCSH_STATE_DIR/statistics.tfplan"
   ```

5. Inspect the planned resource actions.

   ```bash
   terraform -chdir=terraform show -json "$XCSH_STATE_DIR/statistics.tfplan" |
     jq -r '.resource_changes[] | [.address, (.change.actions | join(","))] | @tsv'
   ```

A first deployment plan should contain only creates for the dedicated VMs, networking, namespace, health check, origin pool, blocking WAF, HTTPS load balancer, and generator timer extension. Investigate any update, replacement, or deletion before applying. The origin module permits inbound ports 22, 80, 443, and 8888; the generator permits 22.

## Check idempotence

For a running deployment, use the same pinned configuration, subscription, credentials, and existing private state. A fresh read-only plan checks whether Terraform proposes any change:

```bash
XCSH_PLAN_EXIT=0
terraform -chdir=terraform plan -input=false -detailed-exitcode \
  -out="$XCSH_STATE_DIR/statistics-idempotence.tfplan" || XCSH_PLAN_EXIT=$?
case "$XCSH_PLAN_EXIT" in
  0) printf 'No changes; the deployment is idempotent.\n' ;;
  2) printf 'Changes proposed; investigate before any apply.\n' ;;
  1) printf 'Terraform plan failed; resolve the error.\n' ;;
esac
test "$XCSH_PLAN_EXIT" -eq 0
```

Exit 0 confirms no changes. Exit 2 requires investigation of the saved plan; exit 1 is an error. Retain plans and receipts outside Git. Running resource queries needs no infrastructure apply.

## Apply the reviewed plan

Apply the saved plan:

```bash
terraform -chdir=terraform apply -input=false "$XCSH_STATE_DIR/statistics.tfplan"
```

Follow [Demo readiness](../verification/) after the origin and generator finish cloud-init. Keep the timer running so later API examples have fresh traffic.

## Teardown

Keep the current demo running. Execute these commands only when its owner decides to retire the infrastructure. Use the same credentials, subscription, backend, and state as deployment.

```bash
test -f "$XCSH_STATE_DIR/terraform.tfstate"
terraform -chdir=terraform plan -destroy -input=false \
  -out="$XCSH_STATE_DIR/statistics-destroy.tfplan"
terraform -chdir=terraform show -json "$XCSH_STATE_DIR/statistics-destroy.tfplan" |
  jq -r '.resource_changes[] | [.address, (.change.actions | join(","))] | @tsv'
```

Review every resource address and deletion before applying that exact saved plan.

```bash
terraform -chdir=terraform apply -input=false "$XCSH_STATE_DIR/statistics-destroy.tfplan"
```

Verify that the owned namespace objects and demo DNS answer are absent. Retain the protected local state and ignored `.env` until the owner separately decides to remove them. State, saved plans, and cloud command output may contain credentials or infrastructure identities; keep them outside Git with owner-only permissions.

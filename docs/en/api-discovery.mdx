## Count calls by response class

These POST summary APIs cover API endpoint activity, which can differ from all HTTP access logs. They use `XCSH_VIRTUAL_HOST` and the time window inside `apiep_summary_filter`; the inventory query below uses `XCSH_APP_TYPE`. The summary filter's end is exclusive.

**1. Build a fixed-window summary request.**

```bash
test "$XCSH_API_DISCOVERY_ENABLED" = true
XCSH_REQUEST="$(jq -nc --arg ns "$XCSH_NAMESPACE" --arg vh "$XCSH_VIRTUAL_HOST" \
  --arg start "$XCSH_START_TIME" --arg end "$XCSH_END_TIME" '{
    namespace: $ns, name: $vh,
    apiep_summary_filter: {start_time: $start, end_time: $end}
  }')"
```

**2. Query the returned API-call counters.**

```bash
XCSH_API_CALLS_JSON="$(curl --silent --show-error --fail-with-body --max-time 60 \
  --request POST \
  --header "Authorization: APIToken ${XCSH_API_TOKEN}" \
  --header 'Content-Type: application/json' \
  --data-binary "$XCSH_REQUEST" \
  "${XCSH_API_URL}/api/ml/data/namespaces/${XCSH_NAMESPACE}/virtual_hosts/${XCSH_VIRTUAL_HOST}/api_endpoints/summary/calls_by_response_code")"
jq -er '{total_calls,
  request_count_per_rsp_code: (.request_count_per_rsp_code | sort_by(.rsp_code_class))
}' <<<"$XCSH_API_CALLS_JSON"
```

The actual fields are `total_calls` and `request_count_per_rsp_code`, whose entries contain `rsp_code_class` and `count`. `total_calls` is a JSON string while class counts are numbers. These are request counts, not sampled rates. A missing class is not a measured zero. Keep the API population and window with the output when comparing it to logs.

## Find the busiest endpoints

**1. Request the top five by request percentage.**

```bash
XCSH_REQUEST="$(jq -nc --arg ns "$XCSH_NAMESPACE" --arg vh "$XCSH_VIRTUAL_HOST" \
  --arg start "$XCSH_START_TIME" --arg end "$XCSH_END_TIME" '{
    namespace: $ns, name: $vh,
    apiep_summary_filter: {start_time: $start, end_time: $end},
    topk: 5, top_by_metric: "ACTIVITY_METRIC_TYPE_REQ_PERCENTAGE"
  }')"
XCSH_API_TOP_JSON="$(curl --silent --show-error --fail-with-body --max-time 60 \
  --request POST \
  --header "Authorization: APIToken ${XCSH_API_TOKEN}" \
  --header 'Content-Type: application/json' \
  --data-binary "$XCSH_REQUEST" \
  "${XCSH_API_URL}/api/ml/data/namespaces/${XCSH_NAMESPACE}/virtual_hosts/${XCSH_VIRTUAL_HOST}/api_endpoints/summary/top_active")"
jq -er '{top_apieps: [.top_apieps[]? | {apiep_url, method, top_by_metric_value}]}
' <<<"$XCSH_API_TOP_JSON"
```

`top_by_metric_value` is the integer percentage of requests to that endpoint relative to all API endpoints for this selector. It is not a call count. The default selector ranks security-event percentage; set the request-percentage selector explicitly. Do not assume backend array order is a descending ranking, and do not expect rounded percentages or a top-five subset to sum to 100.

## Read endpoint statistics

**1. Query the virtual host.**

```bash
test "$XCSH_API_DISCOVERY_ENABLED" = true
test -n "$XCSH_VIRTUAL_HOST"
curl --silent --show-error --fail-with-body \
  --header "Authorization: APIToken ${XCSH_API_TOKEN}" \
  --header 'Accept: application/json' \
  "${XCSH_API_URL}/api/ml/data/namespaces/${XCSH_NAMESPACE}/virtual_hosts/${XCSH_VIRTUAL_HOST}/api_endpoints/stats" |
jq -er '{total_endpoints, inventory, discovered, shadow, pii_detected}'
```

Expect `total_endpoints`, `inventory`, `discovered`, `shadow`, and `pii_detected`. Categories can overlap, so their sum need not equal the total.

Captured 2026-10-06 02:14:32 UTC; HTTP 200. These are category counts, not a sum of disjoint sets.

```json

  "inventory": 0,
  "discovered": 3,
  "shadow": 0,
  "pii_detected": 2
}
```

## Read endpoint inventory

**1. Query the app type.**

```bash
test "$XCSH_API_DISCOVERY_ENABLED" = true
test -n "$XCSH_APP_TYPE"
curl --silent --show-error --fail-with-body \
  --header "Authorization: APIToken ${XCSH_API_TOKEN}" \
  --header 'Accept: application/json' \
  "${XCSH_API_URL}/api/ml/data/namespaces/${XCSH_NAMESPACE}/app_types/${XCSH_APP_TYPE}/api_endpoints" |
jq -er '{
  last_update,
  count: (.apiep_list | length),
  categories: ([.apiep_list[]?.category] | group_by(.) |
    map({category: .[0], count: length}))
}'
```

Expect `last_update`, `count`, and category counts. The response filter omits captured paths, request bodies, and sensitive-data details. A newly deployed API route can take time to appear.

In the first live run of this deployment, both queries returned HTTP 200 but reported zero endpoints after a bounded 90-request JSON API burst and 20 minutes of polling. The later measured response below reports three discovered endpoints and three inventory entries. Its `last_update` field is still null, so do not infer a backend refresh time.

Complete [shared cURL setup](../setup/) to match `XCSH_GRAPH_DESTINATION` to the configured origin pool and discover `XCSH_GRAPH_SOURCE`.

Use the destination node's `upstream` metrics for the service receiving requests. The edge's `data.metric.data`
describes the path from the selected source to that destination. Compare rates and errors with response latency, server
RTT, and data transfer time. A high response latency alone does not identify an application bottleneck; server RTT and
transfer time help explain where time was spent.

**1. Request node and edge metrics with service identities retained.**

```bash
XCSH_REQUEST="$(jq -nc --arg ns "$XCSH_NAMESPACE" --arg start "$XCSH_START_TIME" \
  --arg end "$XCSH_END_TIME" --arg vh "$XCSH_VIRTUAL_HOST" '{
    namespace: $ns, start_time: $start, end_time: $end,
    step: "5m", range: "5m", group_by: ["VHOST", "SERVICE"],
    label_filter: [{label: "LABEL_VHOST", op: "EQ", value: $vh}],
    field_selector: {
      node: {metric: {upstream: [
        "HTTP_REQUEST_RATE", "HTTP_ERROR_RATE", "HTTP_ERROR_RATE_4XX",
      "HTTP_ERROR_RATE_5XX", "HTTP_RESPONSE_LATENCY",
      "REQUEST_THROUGHPUT", "RESPONSE_THROUGHPUT", "REQUEST_TO_ORIGIN_RATE",
      "CLIENT_RTT", "SERVER_RTT", "HTTP_SERVER_DATA_TRANSFER_TIME"
      ]}},
      edge: {metric: {types: [
        "HTTP_REQUEST_RATE", "HTTP_ERROR_RATE", "HTTP_ERROR_RATE_4XX",
        "HTTP_ERROR_RATE_5XX", "HTTP_RESPONSE_LATENCY",
        "REQUEST_THROUGHPUT", "RESPONSE_THROUGHPUT", "REQUEST_TO_ORIGIN_RATE",
        "CLIENT_RTT", "SERVER_RTT", "HTTP_SERVER_DATA_TRANSFER_TIME"
      ]}}
    }
  }')"
```

**2. Query the matched node and edge.**

```bash
XCSH_ORIGIN_JSON="$(curl --silent --show-error --fail-with-body --max-time 60 \
  --request POST \
  --header "Authorization: APIToken ${XCSH_API_TOKEN}" \
  --header 'Content-Type: application/json' \
  --data-binary "$XCSH_REQUEST" \
  "${XCSH_API_URL}/api/data/namespaces/${XCSH_NAMESPACE}/graph/service")"
jq -er --arg vh "$XCSH_VIRTUAL_HOST" --arg src "$XCSH_GRAPH_SOURCE" \
  --arg dst "$XCSH_GRAPH_DESTINATION" '
  def summary: {type, unit, points: (.value.raw | length),
                latest: (.value.raw[-1] // null)};
  {step, source: $src, destination: $dst,
   node: ([.data.nodes[]? | select(.id.vhost == $vh and .id.service == $dst)
     | .data.metric.upstream[]? | summary] | sort_by(.type)),
   edge: ([.data.edges[]? | select(.dst_id.vhost == $vh and
     .src_id.service == $src and .dst_id.service == $dst)
     | .data.metric.data[]? | summary] | sort_by(.type))}
' <<<"$XCSH_ORIGIN_JSON"
```

Both arrays must contain metric points before interpreting origin performance. An absent error series is unavailable telemetry, not proof of zero errors. Rate units are per second, throughput is bits per second, and returned latency, RTT, and transfer-time units are preserved. A measured transfer time of `"0"` is a returned value; it does not mean the field was absent.

Demo readiness checks establish that the current HTTP deployment can produce telemetry. Use the landing-page setup for this deployment before checking DNS, TLS, application routes, WAF rejection, and the generator timer.

## Check readiness

For a new deployment, wait for the origin and generator applications to finish provisioning. Use the public routes as the application readiness check.

1. Check DNS and the HTTPS health route.

   <div data-xcsh-context="shell" data-xcsh-fields="XCSH_DOMAINNAME">

   ```bash
   dig +short "$XCSH_DOMAINNAME" A
   curl --silent --show-error --fail-with-body --output /dev/null \
     --write-out 'status=%{http_code} tls=%{ssl_verify_result}\n' \
     "https://$XCSH_DOMAINNAME/health"
   ```

   </div>

   Expect `status=200 tls=0`, which confirms HTTP success and certificate verification.

2. Check an API route through the load balancer.

   <div data-xcsh-context="shell" data-xcsh-fields="XCSH_DOMAINNAME">

   ```bash
   curl --silent --show-error --fail-with-body --output /dev/null \
     --write-out 'status=%{http_code}\n' \
     "https://$XCSH_DOMAINNAME/httpbin/get?statistics_probe=$(date -u +%s)"
   ```

   </div>

3. Check the WAF rejection page with one authorized probe to this F5-owned demo.

   <div data-xcsh-context="shell" data-xcsh-fields="XCSH_DOMAINNAME">

   ```bash
   XCSH_WAF_BODY="$(mktemp)"
   trap 'rm -f "$XCSH_WAF_BODY"' EXIT
   curl --silent --show-error --output "$XCSH_WAF_BODY" --write-out 'status=%{http_code}\n' \
     --get --data-urlencode "q=' OR 1=1--" \
     "https://$XCSH_DOMAINNAME/httpbin/get"
   grep -i '<title>Request Rejected</title>' "$XCSH_WAF_BODY"
   ```

   </div>

   The rejection page can return HTTP 200. Confirm its title and a matching [security event](../security-events/) with `action: "block"`.

4. Check the generator timer on its dedicated VM.

   Authenticate to the approved Azure subscription before using the Azure CLI.

   ```bash
   az vm run-command invoke \
     --resource-group rg-traffic-generator-lab-statistics \
     --name vm-traffic-generator-statistics \
     --command-id RunShellScript \
     --scripts 'systemctl is-active statistics-demo-traffic.timer; cat /var/lib/statistics-demo/run-count' \
     --query 'value[].message' --output tsv
   ```

   Expect `active` and an increasing run count. The timer sends three normal requests each minute and one WAF probe every fifth run. Keep it enabled for fresh telemetry.
